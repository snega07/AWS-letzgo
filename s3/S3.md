## Options and Features

**Global Namespace**

- Resource name must be unique across all AWS accounts and all AWS Regions.
- No two users in the world can create a resource with the same name.
- Used when AWS needs a globally unique identifier (often DNS-based).
Example:
S3 bucket names
Example:
- my-company-data created in us-east-1
- Cannot be created again in ap-south-1 or by another AWS account.

**Regional Namespace**

- Resource name needs to be unique only within a Region or the resource's scope.
- The same name can be reused in another Region.
- Many AWS resources are identified internally by unique IDs, so duplicate names are allowed.
Examples:
VPC names
EC2 instance names
Subnet names
Route table names

**General Purpose Bucket**
- Suitable for most applications.
- Stores objects as key-value pairs.
- Provides high durability and high availability.
- Bucket names are globally unique.
- Data is redundantly stored across multiple Availability Zones within a Region which causes slower writing.
- Also need regional routing while reading the files.

**Directory Bucket (S3 Express One Zone)**
- Designed for ultra-low latency and high request rates(single-digit milliseconds or lower).
- Data is stored in a single Availability Zone. Faster read and write
- Ideal for AI/ML training, analytics, and latency-sensitive workloads.
- Bucket names are unique within an AWS account and Availability Zone(not globally).
- Instead of treating everything as a flat object namespace, it is designed for workloads that frequently access objects grouped under directories.
- A Directory Bucket is still an object store, but its metadata is optimized for operations on directory-like prefixes (such as training/images/), enabling significantly lower latency and higher request rates for workloads like AI/ML, analytics, and high-performance computing.

In a General Purpose bucket, objects are stored in a flat namespace. The folder structure we see is just a prefix in the object key. AWS is optimized for storing and retrieving billions of independent objects, not for workloads that repeatedly access related objects.

In a Directory Bucket, AWS understands the directory structure (directory semantics). This allows AWS to optimize metadata management, request routing, and caching for objects in the same directory, resulting in lower latency and higher throughput.

**ACL(Access Control List) enabled, disabled**

**Enabled**
- Object access can be controlled using ACLs.
- Object ownership can be either Object Writer or Bucket Owner - Preferred/Enforced, depending on the ownership setting.
- Primarily used for legacy applications and certain cross-account access scenarios.

Why does AWS still keep ACLs?

Mainly for:
- Backward compatibility with older applications.
- Some legacy cross-account workflows that still rely on ACLs.
Removing ACLs entirely would break existing systems.
ACLs only understand permissions like:

READ
WRITE
READ_ACP
WRITE_ACP
FULL_CONTROL

**Disabled (Recommended)**

- ACLs are disabled.
- Access is controlled only through IAM policies, Bucket Policies, and Access Points.
- The bucket owner automatically owns every object uploaded to the bucket (Bucket owner enforced).

**Versioning**

- When enabled, S3 maintains multiple versions of an object whenever it is updated or deleted.
- Helps recover from accidental deletion or overwrites.
- Older versions remain available until explicitly deleted or managed by lifecycle rules.
- Lifecycle rules can automatically delete old versions or move them to cheaper storage classes for cost optimization.

Note: Versioning itself does not define a retention period. Retention is controlled using Lifecycle Rules or Object Lock.

**Encrytion type and bucket key**

S3 supports server-side encryption:

- SSE-S3 – Amazon S3 manages encryption keys.
- SSE-KMS – AWS KMS manages encryption keys with audit logging and fine-grained permissions.
- DSSE-KMS – Dual-layer encryption using AWS KMS for enhanced security.

Bucket Key

- Can be enabled only with SSE-KMS.
- S3 caches a data key to reduce the number of requests made to AWS KMS.
- Reduces KMS API costs while maintaining encryption.


**Object lock**

- Requires Versioning to be enabled.
- Protects object versions from deletion or modification for a specified retention period.

Supports:
- Governance Mode – Privileged users can bypass the lock.
- Compliance Mode – No user can bypass the lock until the retention period expires.
- Commonly used for regulatory compliance, audit logs, and financial records.

Object Lock protects individual object versions, not the entire bucket.

**Available storage classes**

Storage class is an object-level property. A single S3 bucket can contain objects belonging to different storage classes. This flexibility is one of the reasons S3 is cost-effective, because each object can use the storage class that best matches its access pattern.

| Storage Class                     | Use Case                                                                                                     |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **S3 Standard**                   | Frequently accessed data with low latency and high throughput.                                               |
| **S3 Intelligent-Tiering**        | Automatically moves objects between access tiers based on usage patterns to reduce costs.                    |
| **S3 Standard-IA**                | Infrequently accessed data that still requires rapid retrieval.                                              |
| **S3 One Zone-IA**                | Infrequently accessed data stored in a single Availability Zone. Lower cost but lower resilience.            |
| **S3 Glacier Instant Retrieval**  | Archive data that requires millisecond retrieval.                                                            |
| **S3 Glacier Flexible Retrieval** | Long-term archive with retrieval times ranging from minutes to hours.                                        |
| **S3 Glacier Deep Archive**       | Lowest-cost storage for long-term archival. Retrieval typically takes 12–48 hours.                           |
| **S3 Express One Zone**           | Ultra-low latency, high-performance storage in a single Availability Zone for AI/ML and analytics workloads. |
